# 配置接纳与运行语义的证据边界

原生 checker 接受语法，不证明字段在该位置被使用，更不能证明代理连通、DNS 路径或系统接管。固定版本目录、精确字段断言和运行请求观测分别回答不同问题；不能拿一个版本的离线接纳替代另一版本或另一平台的证据。

URLTest 的 URL、间隔、容差以及连接中断和空闲策略需要显式编码，不能把不同客户端的默认行为当作共享语义。配置生成器的首条命中解释只返回逻辑出口，不模拟算法实时选中的节点。

批次提交后的清理失败与未发布失败必须区分。仅检查 published 会掩盖非零维护状态；调用方应透传 exitCode 并保留恢复信息。实体目录恢复失败后保留现场，比盲目自动清理更有利于恢复完整配置。
